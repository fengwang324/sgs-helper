## 建议：需要拆仓时采用两个仓库

此方案为讨论建议，尚未拆分或创建仓库。

| 仓库职责 | 内容 |
| --- | --- |
| 资料库 | 唯一权威YAML、稳定ID、卡图、模型及校验、SQLite构建、前端数据导出；编辑工具同仓、按需启动 |
| 用户展示页 | HTML/CSS/JavaScript、手机与桌面图鉴；消费资料库导出的catalog与所需图片，不维护第二份权威YAML |

理由：展示页适合独立前端维护和小程序资源打包；编辑工具直接写数据，必须与模型、校验及写回流程同步，当前放在资料库同仓更容易维护。数据库修正只在资料库进行，再由明确的导出/同步步骤更新展示页使用的数据快照。

“纯数据库”“数据库＋展示”“数据库＋编辑”可以是三种导出或安装方式，不必各维持一条不同数据版本的长期分支。若坚持三个独立仓库，编辑仓还需处理共享模型、数据读写、依赖版本和配套验证，当前没有必要增加这一层维护。

当前编辑网页为历史工具，仍需按最新数据结构重新适配及验收；拆出一个分支或仓库不会使旧工具自动恢复可用。本轮不启动编辑网页重构。
