# 更新记录

每次改动都必须在这里留一条记录：**改了什么 → 为什么 → 自查有没有做多余的事**。

## 约定

1. 动手前先明确本次任务的**目标**，写进记录的「目标」一行。
2. 改完后如实写「改动清单」，包括顺手做的事（不许瞒）。
3. 写「自查」：逐条对照目标，检查有没有超出范围的改动。
   - 发现偏移 → **不 commit**，把多余的部分回退，重做任务。
   - 确认无偏移 → 正常 `commit` + `push`。
4. 新记录写在最上面（倒序），格式照抄下面的模板。

### 记录模板

```markdown
## YYYY-MM-DD 一句话标题

**目标**：本次要达成什么（用户原话要点）。

**改动清单**
- 数据：…
- 代码：…
- 文档：…
- 测试：…

**自查（有无多余 / 偏移）**
- [x] 逐条对照目标，没有超范围的改动
- 说明：…（哪些是「顺带但必要」，为什么必要）
- 被舍弃的改动：…（如有，说明为什么不 commit）

**验证**：跑了什么、结果如何。
**提交**：`<sha>`（未提交则写明「未提交，原因」）
```

## 2026-10-07 武将卡图：文件名完全由系统接管，用户不用填

**目标**：用户问「我新建武将的话会通过编号添加上传的武将图名字吗」，
随后明确「卡图名字我不用填，你自己接收后修改名字不就行啦」。

**问题（实测复现，不是猜的）**
上传接口沿用浏览器给的原始文件名，而 YAML 的 `image` 字段来自表单；前端上传后
把返回的文件名回填进 `image`。于是：

```text
上传 IMG_2043.png + 编号 G.TEST 001
  -> YAML 写 image: IMG_2043.png
  -> 按编号应叫 g_test_001.jpg（不存在）
```

即 `id` 与 YAML 文件名都遵守了编号派生，**只有卡图名没遵守**，上传完就找不到图。

**走过的弯路（记录在案）**
第一版做成了「上传时就按编号命名 + 保存时校验文件名必须与编号一致」，
需要用户**先填编号再上传**，不符还会报错。用户指出这是多余的门槛：
文件名不该由用户操心。已按此**推翻重做**，改为保存时静默改名。

**最终改动清单**
- 代码：`editors` 里武将的 `image` 一律改写成编号派生名，**不校验、不报错**；
  用户的原始文件名只是用来在写盘后把那个文件改名。
- 代码：`Change` 新增 `uploaded_image` 字段承载「用户刚上传的文件名」。
  **不放进 `candidate` dict**——模型是 `extra="forbid"`，会直接被校验拦下（踩过）。
- 代码：`store.save_batch` 写盘后把该文件改成编号派生名（`_move_renamed_images`）。
- 代码：扩展名**保留**（上传 `.png` 就叫 `g_test_001.png`，不硬写成 `.jpg`），
  避免内容与后缀不符；取不到时依次回退到「磁盘上同编号文件 → 旧文件名 → `.jpg`」。
- 代码：`IMAGE_SUFFIXES` 上移到 `constants.py`，上传与卡图名派生共用一份，避免口径漂移。
- 代码：`/api/upload-image` **退回简单实现**（只落盘、不改名），不再需要 `number` 参数。
- 前端：`wiki-upload.js` 退回简单实现（不传编号、不拦空编号）；
  `general_edit.html` 文案改为「选好图保存即可，文件名不用管」。
- 测试：`test_wiki.py` 新增用例——上传 `IMG_2043.png`，保存后 YAML 是
  `g_test_001.png`、磁盘上确实是它、原上传名不残留。
- 文档：本条记录。

**自查（有无多余 / 偏移）**
- [x] 本条目本身是对上一版自查结论的**推翻**：上一版「上传即按编号命名 +
  校验拦截」被判定为**偏移**（给用户加了没要求的门槛），已回退重做，未 push。
- [x] 最终改动严格限于「卡图文件名由系统接管」这一件事。
- 说明：`IMAGE_SUFFIXES` 上移 `constants.py` 是消除重复定义（原先只在 `wiki.py`），
  不是顺手重构——`editors` 需要同一份白名单才能安全判断扩展名。
- 说明：扩展名保留是**必要**的。若一律写 `.jpg`，上传 PNG 会得到
  content 是 PNG 但后缀叫 `.jpg` 的文件，属于制造新的不一致。
- 已知边界（未改，记录在案）：从模板或已有武将「复制新建」时若预填旧卡图，
  保存后该文件会被改成新编号的名字——实际取的是那张旧图。用户说不用管文件名，
  故未加限制；若要「新建时必须重新选图」需另提。
- 被舍弃的改动：上传接口的 `number` 参数、`wiki-upload.js` 的
  `data-upload-number-field`、`editors` 的 image 名校验与报错——
  **全部删除**，第一版的检查点已 amend 覆盖，未 push。

**验证**（只跑改动相关，未跑全量）
- 脚本实测：上传 `IMG_2043.png` + 编号 `G.TEST 001` → YAML `image: g_test_001.png`，
  磁盘只剩 `g_test_001.png`，原上传名不残留。
- 脚本实测：改编号 `G.TEST 001 → G.TEST 002` → 图片改名 `g_test_002.png`，无残留。
- `data/` 未受影响：356 个卡图仍全为 `.jpg`，`validate_data.py` → 0 错误。
- `pytest tests/test_wiki.py tests/test_admin_editors.py tests/test_admin.py` → **135 条通过**。
