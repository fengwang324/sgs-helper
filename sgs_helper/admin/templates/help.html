使用说明

这个页面能做什么

  • 统一搜索 {{ KIND_ORDER | length }} 类实体，看结果类型、名称、模式、来源；
  • 逐类浏览列表，按 mode / 产品 / 系列（拓展包）/ 分类 筛选；
  • 查看详情：技能看 SkillDefinition → 当前版本 → 历史版本链；卡牌看单层 Card（一 / 二 / 三级分类 · 卡名 · 拓展包 · 效果文本 · 关联技能）；武将看关联技能及其 SkillVersion；
  • 新增与编辑：产品与武将、卡牌各有专用录入页（字段顺序固定、联动下拉、技能行）；其余低频实体用通用表单；
  • 技能更新用「新增技能版本」，旧版本永不覆盖；
  • 删除前会检查引用关系，被引用就拒绝删除并列出引用方。

新模型下的几个约定

  • review_note（复核备注）只出现在 武将版本 / 技能版本 / 卡牌 / 技能 四类表单里。
  • 卡牌是单层的：一 / 二 / 三级分类表达“这张卡是什么”，card_set 表达“它来自哪个拓展包”，两者完全独立； 同一规则卡的不同实体印刷不在这一层建模，卡牌也没有 mode / source 字段。
  • 基本牌的最后一级是卡名：游戏牌/基本牌/杀 下面是 杀 / 火杀 / 雷杀， 所以基本牌的 category_3 只写牌族（杀 / 闪 / 桃 / 酒），具体是哪一张写在 name。
  • 自动关联：FAQ 详情页对 question + answer、技能详情页对技能文本调用 repo.mentions(conn, text)，按实体名称自动识别武将 / 技能 / 卡牌 / 关键词 / 时点并渲染成可点击链接； 手工维护的关联 id 字段已全部删除。
  • 武将牌系列只维护两处：产品里的 general_sets（候选全集）与武将版本的 general_set（具体归属）。
  • 游戏牌拓展包只维护两处：产品里的 card_sets（候选全集）与卡牌的 card_set（具体归属），卡牌自己不能发明拓展包名。

核心原则：YAML 是唯一权威源

浏览器编辑 → 写回 data/ 下的 YAML → validate → build_db → SQLite 更新
  • 网页不会直接修改 build/sgs.db；SQLite 只是生成物，可随时全量重建；
  • 保存时先在内存里把改动合并进完整数据集做一次校验，校验不通过就一个字都不落盘；
  • 写盘成功后会立即执行 build_database() 重建 SQLite（先建临时库，成功后原子替换，失败则回滚 YAML）；
  • 本页展示的数据始终直接读自 YAML，所以永远不会出现“看到的是旧值、改的却是新值”。

命令行等价操作

python scripts/validate_data.py     # 校验
python scripts/build_db.py          # 由 YAML 全量重建 build/sgs.db
python scripts/query.py skill 集智  # 查询（只读 SQLite）
python -m pytest -q                 # 测试
uvicorn sgs_helper.admin.app:app --host 127.0.0.1 --port 8000   # 本页面

已知限制（有意为之）

  • 写 YAML 时会规范化格式：字段顺序按模型顺序、长文本改成块状标量（|-）， 记录内部的行内注释、锚点/别名不会被保留；文件顶部的注释块会保留。
  • 一个文件里放了多条记录时（例如 data/keywords/core_keywords.yaml），编辑其中一条会整文件重写（其他记录内容不变，格式会被规范化）。
  • 列表字段（武将牌系列、游戏牌拓展包等）用“一行一项”的文本框，空行会被忽略，前后空格会被去掉。
  • 本地工具：没有登录和权限控制，默认只监听 127.0.0.1。如果用 --host 0.0.0.0 暴露到局域网，请自行确保网络环境可信（表单带 CSRF token，但这不是完整的认证）。
  • 不是正式微信小程序，也不提供 API 给小程序的鉴权/限流。
